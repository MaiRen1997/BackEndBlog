minIO的安装

# 单机部署为例。

# 1. 创建存储目录

例如：

mkdir -p /data/minio
mkdir -p /data/minio-data
1
2

目录说明：

/data/minio         # MinIO程序
/data/minio-data    # 对象存储数据
1
2

# 2. 下载 MinIO

进入安装目录

cd /data/minio
1

下载最新版

wget https://dl.min.io/server/minio/release/linux-amd64/minio
1

如果 wget 不行，可以使用 curl

curl -O https://dl.min.io/server/minio/release/linux-amd64/minio
1

赋予执行权限

chmod +x minio
1

移动到系统目录

mv minio /usr/local/bin/
1

检查是否安装成功

minio --version
1

应该看到类似

minio version RELEASE.2025-xx-xx
1

# 3. 创建运行用户（推荐）

不要使用 root。

useradd -r minio -s /sbin/nologin
1

授权目录

chown -R minio:minio /data/minio-data
1

# 4. 创建配置文件

创建

vim /etc/default/minio
1

写入

MINIO_ROOT_USER=admin
MINIO_ROOT_PASSWORD=12345678

MINIO_VOLUMES="/data/minio-data"

MINIO_OPTS="--console-address :9001"
1
2
3
4
5
6

说明：

  • API端口：9000
  • 控制台：9001

# 5. 创建 systemd 服务

创建

vim /etc/systemd/system/minio.service
1

内容：

[Unit]
Description=MinIO
After=network.target

[Service]
User=minio
Group=minio

EnvironmentFile=/etc/default/minio

ExecStart=/usr/local/bin/minio server $MINIO_VOLUMES $MINIO_OPTS

Restart=always

LimitNOFILE=65536

[Install]
WantedBy=multi-user.target

# 6. 重新加载 systemd

systemctl daemon-reload
1

设置开机启动

systemctl enable minio
1

启动

systemctl start minio
1

查看状态

systemctl status minio
1

如果看到

Active: active (running)
1

说明启动成功。

# 7. 开放防火墙

CentOS7 默认 firewalld：

firewall-cmd --permanent --add-port=9000/tcp
firewall-cmd --permanent --add-port=9001/tcp

firewall-cmd --reload

# 8. 登录控制台

浏览器访问：

http://服务器IP:9001
1

例如：

http://192.168.1.100:9001
1

登录：

用户名：admin
密码：12345678
1
2

登录成功后即可：

  • 创建 Bucket
  • 上传文件
  • 创建用户
  • 创建 AccessKey
  • 设置权限

# 10. 常用命令

查看日志：

journalctl -u minio -f
1

停止：

systemctl stop minio
1

重启：

systemctl restart minio
1

开机启动：

systemctl enable minio
1

取消开机启动：

systemctl disable minio
1

# 生产环境建议

如果你计划将 MinIO 用于生产环境（例如 FastAPI + Vue 文件上传、AI 知识库存储、对象存储等），建议进一步配置：

  • 使用 Nginx 反向代理，将 9000/9001 映射到 80/443。
  • 配置 HTTPS（TLS 证书）。
  • 修改默认的 admin 用户名和密码。
  • 使用独立磁盘（如 /data1、/data2）存储数据。
  • 配置定期备份。
  • 如果数据量较大或需要高可用，采用官方推荐的 多节点多磁盘（Distributed） 部署，而不是单节点。
